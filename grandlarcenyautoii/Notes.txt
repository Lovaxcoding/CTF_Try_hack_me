Là, on vient de trouver quelque chose de beaucoup plus intéressant qu'une simple version vulnérable de Kestrel.

private static readonly byte[] SignKey = Encoding.UTF8.GetBytes("gla2_crew_sign_v1_2f9b6c8ad14e"); sur popclient avec ilspy

Le client contient une clé HMAC codée en dur, une fonction de signature, deux endpoints supplémentaires et un mécanisme de calcul de rôle à partir de l'ordre des braquages. Ce sont des pistes concrètes pour comprendre comment le backend valide les actions du joueur.
On va analyser ça comme en reverse engineering : comprendre le protocole, formuler des hypothèses, puis les tester sur la machine TryHackMe.

Grâce à PoPClient, nous connaissons désormais trois endpoints :
Endpoint	Méthode	Fonction supposée
/session	POST	Créer une session et obtenir les paramètres nécessaires.
/checkpoint	POST	Signaler une étape du braquage.
/claim	POST	Réclamer le résultat final.

Pour calculer la signature d'un checkpoint, la formule exacte trouvée dans ton code est :
HMAC-SHA256(
    clé = SignKey,
    message = session_id + "|" + step + "|" + token
)

La signature attendue est le digest hexadécimal en minuscules. La clé elle-même n'est pas la signature : c'était le problème dans ta requête précédente.
